When each documentation type renders

Conditions for every one of the 93 catalogue entries: pages, blocks and diagrams, including 1 open coverage entries and the unsupported deferred template. Each rule states the required input, the condition for populated content, and what happens when data is absent or rejected.

A page shell or a gap placeholder is not a populated example. Rendering, source freshness, meaning review and runtime verification are separate. Unless an entry states a newer renderer revision, these rules describe source revision 31a559851b947d5eda90afc003f2bfb2b2c27130; they do not create or modify native output, accepted business prose or provenance.

Common admission rules

Each entry below names one of these routes. Apply its admission rule before the entry-specific display condition.

Frozen service/process publication
Input route
docs pages render --root ROOT --snapshot SNAPSHOT --publication PUBLICATION --output EMPTY_DIRECTORY
Admission
The immutable snapshot and saved publication must load. Frozen manifests, safe paths, content digests and canonical operations must validate. Full publication rendering rejects endpoint exclusions. Output must be new or empty; no model authoring occurs.
Limits
An existing saved narrative can be displayed with STALE, UNVERIFIED or UNASSESSED labels. A missing requested-language translation replaces the affected narrative with a translation gap. Rendering does not grant meaning review or prove runtime behavior.
Selected native declaration pages
Input route
docs pages render --root ROOT --snapshot SNAPSHOT --input SELECTIONS_JSON --output EMPTY_DIRECTORY
Admission
Supply 1–128 exact selections, with unique nonempty IDs, service, endpointDeclaration and workerDeclaration; wiringDeclaration is optional. Applicable captured evidence, source coordinates and publication policy determine the admitted projection. Output must be new or empty.
Limits
Selection does not imply source behavior: declaration-only, compiler CFG and source-call expansion have different capabilities. Unsupported evidence produces a local gap or rejects an incompatible selection; no missing behavior is invented.
OperationAnswer business reader
Input route
A retained endpoint/process packet and its structurally valid OperationAnswer; docs work explain input mode or a saved review-run export.
Admission
Validate the supported answer schema, exact packet binding, cited evidence labels, semantic IDs and references. Plain input rendering may remain DRAFT / UNREVIEWED / NOT_PUBLISHED. Review-run export additionally requires one durable approved unpublished answer bound to that exact work, checkpoint and snapshot.
Limits
A locally rendered reader, even with model approval, is not automatically a published service narrative. Optional rich blocks depend on their answer/packet fields and supported schema.
Explicit Java flow DSL projection
Input route
An explicit codeclew-flow-dsl-profile/1.0 plus retained real Java methods; builder-chain or operation-queue family.
Admission
Validate exact method/file/owner/scope bindings and the selected DSL family. The extractor must recognize the bounded Java AST construction; the publisher writes only new files and refuses collisions.
Limits
AST method references and declared operation queues are static declarations. They do not prove dispatch, execution, completion or deployed activation.

Admission

Limits

Blocks

First-match decision table and outcome details

Common admission rule: OperationAnswer business reader.

Required inputs
A decision whose otherwise consists of exactly one next decision, forming a chain; retained branch children and any final otherwise outcome.
Shows populated content when
first_match_table follows that chain and renders an inline table only when decision-branch count plus a nonempty final otherwise exceeds two. Outcome details retain each branch’s steps.
If inputs are missing or rejected
A simple if/else or smaller chain stays ordinary nested behavior; no artificial third outcome is added.
Authority and limits
This automatic answer projection is distinct from a typed visual decision-table and its explicit hitPolicy.
