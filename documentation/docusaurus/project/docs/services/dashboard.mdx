## Overview {#section-overview}

<details>
<summary>Full retained description and supporting source</summary>

Retained account · UNVERIFIED · UNASSESSED. Runtime behavior is not established by this export.

Dashboard serves saved place cards and accepts save and forecast-refresh requests for Places. It also consumes weather.place-requested and weather.forecast-updated events to maintain local cards. Six HTTP roots are GET /, GET /api/weather, POST /api/places, POST /api/places/&#123;id&#125;/refresh, GET /health, and GET /openapi.json. Source start connects Kafka, subscribes from the beginning to both topics, starts the shared consumer with autoCommit false, registers those routes, then listens; this source sequence does not establish runtime activation. The consumer validates recognized topic/event pairs and applies valid events transactionally. Parse or validation failures are persisted before offset plus one is committed; persistence failure prevents the commit, while an unknown topic throws UNKNOWN\_TOPIC. The event schema and OpenAPI file are declarations, not proof of runtime enforcement. The capture uses TypeScript source syntax with declared dialect 7.0.2 and file-only browser, contract, schema, and database inputs; runtime and compiler validation remain UNKNOWN. See GET / for browser behavior and each HTTP operation for its declared contract.

<details>
<summary>Full retained description and supporting source</summary>

Retained account · UNVERIFIED · UNASSESSED. Runtime behavior is not established by this export.

The captured Dashboard source serves a home page and saved weather-card JSON, forwards place-save and refresh requests to Places, and subscribes to weather.place-requested and weather.forecast-updated. The consumer dispatches each message to validation and event handling. In a transaction, applyEvent first inserts the event id into inbox; a duplicate commits and returns before any weather\_cards upsert. A new place request updates place details. A forecast event inserts a missing card, or updates a conflicting card only when its stored updated\_at is null or the incoming updatedAt is strictly newer; an older or equal event can commit its inbox row without changing the card. The health handler probes PostgreSQL and checks a local consumerReady flag. These statements describe source paths and declared registrations, not runtime activation.

## Domain entities {#section-entities}

Reading outline · verbatim excerpts; open the full description for all qualifications.

- The service validator checks an event id, version 1, and a place with id, name, latitude, and longitude.

<details>
<summary>Full retained description and supporting source</summary>

Retained account · UNVERIFIED · UNASSESSED. Runtime behavior is not established by this export.

The service validator checks an event id, version 1, and a place with id, name, latitude, and longitude. A weather.forecast-updated event must carry a forecast with updatedAt, fetchedAt, mode, and one to six periods; each period is checked for a timestamp, numeric temperature, null or nonnegative numeric precipitation, and a string symbol. The weather\_cards upsert stores place fields, updated\_at, and the forecast JSON. The inbox table is used for event-id duplicate handling, while rejected\_messages records topic, partition, offset, and reason. These shapes come from code checks and SQL statements, not a fully interpreted shared JSON Schema.

## Egress contracts {#section-egress}

- The save and refresh handlers send POST requests to the configured Places base URL with a ten-second timeout.

<details>
<summary>Full retained description and supporting source</summary>

Retained account · UNVERIFIED · UNASSESSED. Runtime behavior is not established by this export.

The save and refresh handlers send POST requests to the configured Places base URL with a ten-second timeout. Save sends the request body as JSON; refresh appends the encoded place id and sends no body. Both forward the upstream status and parsed JSON response, and both return 503 with PLACES\_UNAVAILABLE when an exception is caught. For consumed messages, the invalid branch attempts a rejected\_messages insert and then calls commitOffsets for offset plus one. The valid branch waits for applyEvent and then calls commitOffsets; a thrown handler or database error exits before that call in the shown body. applyEvent uses a PostgreSQL transaction for inbox and weather\_cards writes. The source shows call order, not cross-store atomicity or broker delivery guarantees.
