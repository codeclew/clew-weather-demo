## Identity and relationships {#identity-and-relationships}

This request has no durable request ID in the captured shape. cityId selects Place.id. A new outbox event gets a separate Guid; a 200 response is not an acknowledgement of Kafka publication or forecast readiness.

### cityId {#field-city-id}

The selected city key sent by the browser. This request carries only cityId; Places derives the Place name and coordinates from its supported-city lookup. It is not an event ID, and it is not a client-supplied Place object.

<summary>Declared Places save request</summary>

Derived from the request schema · Declared required request property · Derived from the schema

The declared POST /places JSON body requires cityId, one of oslo, helsinki or lisbon, and disallows extra properties. This is the receiving contract, not proof that Dashboard validates the request.
