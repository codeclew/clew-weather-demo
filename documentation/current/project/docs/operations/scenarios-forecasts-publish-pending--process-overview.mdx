# Publish pending forecast updates

<ClewPageContext />

Retained account · STALE · UNASSESSED. Runtime behavior is not established by this export.

The source declares publishPending on a fixed-delay schedule with a 1,000 ms default; runtime activation remains unverified. Each invocation selects at most one unpublished outbox row by ID using FOR UPDATE SKIP LOCKED, returning when none is available. For a selected row, it sends the stored payload to weather.forecast-updated with the place ID as key, waits up to ten seconds, then marks the row published in the database transaction. An exception is logged as PUBLISH\_RETRY. Because broker send and database commit are separate effects, a crash can leave the row eligible for replay. The linked Dashboard consumer is an unassessed separate view, so delivery and downstream completion are not established.
